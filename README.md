# <img align="absbottom"  src="https://raw.githubusercontent.com/EgorTatarnikov/Kepler_MVP/main/kepler-logo-vector_3.svg" width="36" height="36"> Кеплер: платформа с ИИ-инструментами для задач инженера

**Кеплер** - это локальное Windows-приложение, которое помогает инженеру искать информацию, работать с техническими документами и готовить служебные материалы.

**Презентация:** [Описание проекта и скриншоты приложения (PDF)](./Кеплер%20-%20Презентация%20приложения.pdf)  

## Цель Кеплера
Сделать современные ИИ-технологии прикладным инструментом инженера, сократить объём рутинной работы и обеспечить инженера нужной информацией для конструирования, анализа и принятия технических решений.

## Инструменты Кеплера

В приложении для каждой типовой задачи сотрудника предусмотрен отдельный инструмент. Пользователь выбирает необходимое действие: получить инженерную консультацию, найти информацию по смыслу, сравнить версии документов, подготовить документ по шаблону или распознать текст со скана. Результаты работы одного инструмента могут передаваться в другие, образуя последовательный процесс работы с информацией. 

### 1. Консультант

Инструмент предназначен для взаимодействия с локальной языковой моделью на естественном языке человека. Он позволяет:
- получать пояснения по техническим вопросам;
- анализировать приложенные документы;
- составлять краткие резюме;
- улучшать инженерные формулировки;
- выявлять противоречия и недостающие данные.

### 2. Корпоративная база знаний и RAG

Для подкрепления ответов модели реальными данными была собрана база знаний со справочной информацией по конструированию, материаловедению, нормативным документам и другим темам.

RAG-модуль обеспечивает формирование ответов на основании выбранных документов. Перед передачей запроса языковой модели программа:
- обрабатывает и индексирует документы;
- ищет релевантные фрагменты;
- передаёт найденные данные модели;
- формирует ответ со ссылками на использованные источники.
  
Пользователь может выбрать конкретный документ или базу знаний, которая должна использоваться при подготовке ответа. Это снижает риск формирования неподтверждённых сведений и позволяет проверять результат.

### 3. Семантический поиск

Инструмент предназначен для поиска информации по смыслу, а не только по точному совпадению слов. Программа преобразует запрос и фрагменты документов в векторные представления и определяет их смысловую близость.

Это позволяет находить информацию при использовании:
- разных формулировок одного требования;
- сокращений и полных названий;
- официальных и разговорных технических терминов;
- близких по смыслу понятий.
  
Поиск может выполняться по выбранным папкам, документам или локальной базе знаний.

### 4. Сравнение документов

Инструмент совмещает классическое алгоритмическое сравнение и анализ языковой моделью.
Классические алгоритмы выявляют:
- добавленные и удалённые фрагменты;
- изменение числовых значений;
- изменение обозначений;
- перестановку или переформулирование текста.
  
Языковая модель интерпретирует технический смысл изменений: появление нового требования, ужесточение условия, изменение параметра или отсутствие смысловых изменений. По результатам формируется сводный отчёт.

### 5. Подготовка документов

Инструмент предназначен для автоматизированного создания служебных записок и других типовых документов.

Пользователь вводит исходные данные и текст в свободной форме. После этого программа:
- преобразует текст в инженерный деловой стиль;
- устраняет повторы, тавтологию и разговорные формулировки;
- структурирует требования и исходные данные;
- заполняет корпоративный шаблон;
- проверяет наличие обязательных полей;
- формирует готовый документ в формате DOCX.
  
При этом языковая модель отвечает за работу с текстом, а заполнение шаблона и сохранение файла выполняются классическими алгоритмами.

### 6. Распознавание документов

OCR-инструмент преобразует сканы, изображения и PDF без текстового слоя в редактируемый текст.

Результат можно:
- проверить и отредактировать;
- сохранить в текстовый формат;
- передать инженерному консультанту;
- включить в семантический поиск;
- добавить в корпоративную базу знаний.
  
Это позволяет использовать архивную документацию, ранее недоступную для автоматического поиска и анализа.

### 7. Взаимодействие инструментов

Инструменты Кеплера взаимосвязаны и образуют единый рабочий процесс: распознанный документ можно добавить в базу знаний, найти в нём требования, сравнить их с новой редакцией и использовать результаты при подготовке итогового документа.

## Описание проблемы

Идея Кеплера появилась из моего опыта работы инженером-конструктором. 

Современное производство генерирует большие объемы данных на всех этапах жизненного цикла изделия. Количество информации растет быстрее возможностей сотрудников по её поиску и обработке. 

Значительная часть времени инженера уходит не на разработку, а на:

- поиск и изучение документов;
- погружение в контекст проекта;
- поиск ранее принятых решений;
- сверку требований и параметров;
- сравнение разных версий документов;
- подготовку служебных материалов.

При этом данные хранятся разрозненно и часто представлены в виде сканов и изображений, недоступных для обычного текстового поиска.

Это увеличивает сроки выполнения работ, приводит к повторному решению уже рассмотренных задач, снижает использование накопленного опыта и повышает риск пропуска требований. Иногда разработать решение заново оказывается проще, чем найти существующий аналог.

## Поиск решения

### Существующие инструменты

Большинство этих задач уже можно частично решать с помощью отдельных программ.

Для создания локального ИИ-консультанта с RAG существуют **LM Studio** и аналогичные решения. Они позволяют запускать языковые модели локально и работать с документами. Однако универсальные RAG-инструменты не достаточно адаптированны для работы с технической документацией. 

Для распознавания сканов существуют отдельные OCR-программы.

Для сравнения документов можно использовать, например, встроенные средства Microsoft Word. Они хорошо показывают формальные изменения текста, но не предназначены для объяснения их инженерного смысла. 

Подготовку документов можно частично автоматизировать шаблонами и отдельными средствами работы с текстом, но такие решения приходится адаптировать под конкретные формы документов и рабочие процессы.

Таким образом, необходимые инструменты существуют, но они представлены в виде отдельных программ. Их приходится настраивать, связывать между собой и адаптировать под конкретные инженерные сценарии.

Это привело меня к идее создать собственную платформу, в которой необходимые инструменты объединены в одном приложении и могут использовать результаты работы друг друга.

### Свое решение

Я выбрал формат локального приложения с отдельным инструментом для каждой типовой задачи. 

Кеплер представляет собой локальную программную платформу для решения задач инженера. Платформа реализована в виде Windows-приложения, объединяющего LLM (большие языковые модели), RAG (ответы с опорой на реальные данные), семантический поиск, OCR (распознавание текста) и классические алгоритмы обработки документов.

В качестве языковых моделей могут использоваться LLM в GGUF формате. Выбор конкретной модели зависит от требований к качеству, производительности и вычислительным ресурсам рабочего места.

Пользователь выбирает нужное действие: задать вопрос, найти информацию, сравнить документы, распознать скан или подготовить служебную записку. Ему не требуется разбираться в устройстве ИИ, RAG и векторного поиска.

Особенность Кеплера заключается в объединении функций в едином рабочем процессе. Результат распознавания можно передать в поиск или консультант, найденные сведения использовать при подготовке документа, а изменения между версиями проанализировать с помощью ИИ. 

Собственная разработка позволяет оперативно дорабатывать инструменты по обратной связи пользователей и адаптировать их под реальные рабочие сценарии в предприятии.

Приложение работает без подключения к Интернету. Языковые модели и документы хранятся локально, а обработка информации выполняется на компьютере пользователя. Локальная работа - это одно из основных ограничений проекта, связанных с требованиями безопасности предприятия с закрытым информационным контуром.

## Реализация

| Компонент | Технологии и назначение |
| --- | --- |
| Приложение для Windows | Tauri — настольная оболочка |
| Пользовательский интерфейс | React и TypeScript |
| Логика приложения | Rust — обработка документов и координация инструментов |
| Локальные модели | llama.cpp и формат GGUF — запуск языковых и embedding-моделей |
| Хранение данных | SQLite — история, документы, индексы и результаты работы |
| Поиск | SQLite FTS5 и векторный поиск с объединением результатов |
| Распознавание текста | Tesseract OCR |

Для генерации ответов и поиска используются модели с разными задачами: языковая модель формирует текст, embedding-модель преобразует запросы и фрагменты документов в векторы для оценки смысловой близости.

**Почему выбран гибридный поиск.** В инженерных документах важны и смысл, и точные обозначения: марки материалов, номера требований, термины и числовые параметры. При исследовании подходов я пришёл к выводу, что одной векторной близости для таких задач недостаточно. Поэтому в приложении объединены полнотекстовый и семантический поиск: первый помогает находить точные совпадения, второй — связанные по смыслу фрагменты с другими формулировками.

Обработка документов, поиск, генерация и интерфейс разделены на модули. Это позволяет дорабатывать отдельные инструменты и расширять приложение по мере проверки рабочих сценариев.
