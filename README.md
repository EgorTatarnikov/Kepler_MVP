# <img align="absbottom"  src="https://raw.githubusercontent.com/EgorTatarnikov/Kepler_MVP/main/kepler-logo-vector_3.svg" width="36" height="36"> Кеплер: платформа с ИИ-инструментами для задач инженера

**Кеплер** - это локальное Windows-приложение, которое помогает инженеру искать информацию, работать с техническими документами и готовить служебные материалы.

## Цель Кеплера
Сделать современные ИИ-технологии прикладным инструментом инженера, сократить объём рутинной работы и обеспечить инженера нужной информацией для конструирования, анализа и принятия технических решений.

## Инструменты Кеплера

В приложении для каждой типовой задачи сотрудника предусмотрен отдельный инструмент. Пользователь выбирает необходимое действие: получить инженерную консультацию, найти информацию по смыслу, сравнить версии документов, подготовить документ по шаблону или распознать текст со скана. Результаты работы одного инструмента могут передаваться в другие, образуя последовательный процесс работы с информацией. 

### 1. Инженерный консультант

Чат с локальной языковой моделью для пояснения технических вопросов, анализа приложенных документов, подготовки кратких резюме и улучшения формулировок.

К консультанту можно подключить базу знаний. В этом режиме приложение находит подходящие фрагменты документов и передаёт их модели вместе с вопросом. Ответ сопровождается ссылками на использованные источники, чтобы пользователь мог проверить исходные сведения. Такой подход называется RAG — генерация ответа с опорой на найденные материалы.

### 2. ИИ-поиск

Поиск информации по локальным документам и базам знаний. Сочетает поиск по словам и смысловой близости, чтобы находить материалы при различиях в формулировках запроса и исходного текста.

Пользователь видит найденные фрагменты и их источники. Результаты можно использовать для дальнейшей работы с консультантом.

### 3. Сравнение документов

Сопоставление двух версий документа с выделением добавленных, удалённых и изменённых фрагментов, включая изменения числовых значений.

Результат можно обсудить в чате: попросить модель объяснить суть изменений и обратить внимание на возможные изменения требований или параметров. Отчёт о сравнении сохраняется в DOCX.

### 4. Распознавание текста

Преобразование печатного русского и английского текста на изображениях и в сканированных PDF в редактируемый текст.

Результат можно проверить, исправить, сохранить в TXT или DOCX и передать в чат для дальнейшего анализа.

### 5. Подготовка документов

Создание служебных записок по короткой форме: пользователь указывает реквизиты и описывает содержание своими словами. Приложение помогает оформить текст в инженерном деловом стиле, заполнить шаблон и сохранить документ в DOCX.

Перед сохранением результат доступен для просмотра и редактирования. Каталог шаблонов предусмотрен для дальнейшего расширения.

## Описание проблемы

Идея Кеплера появилась из моего опыта работы инженером-конструктором. 

Современное производство генерирует большие объемы данных на всех этапах жизненного цикла изделия. Количество информации растет быстрее возможностей сотрудников по её поиску и обработке. 

Значительная часть времени инженера уходит не на разработку, а на:

- поиск и изучение документов;
- погружение в контекст проекта;
- поиск ранее принятых решений;
- сверку требований и параметров;
- сравнение разных версий документов;
- подготовку служебных материалов.

При этом данные хранятся разрозненно и часто представлены в виде сканов и изображений, недоступных для обычного текстового поиска.

Это увеличивает сроки выполнения работ, приводит к повторному решению уже рассмотренных задач, снижает использование накопленного опыта и повышает риск пропуска требований. Иногда разработать решение заново оказывается проще, чем найти существующий аналог.

## Поиск решения

### Существующие инструменты

Большинство этих задач уже можно частично решать с помощью отдельных программных инструментов.

Для создания локального ИИ-консультанта с RAG существуют **LM Studio** и аналогичные решения. Они позволяют запускать языковые модели локально и работать с документами, однако универсальные RAG-инструменты не достаточно адаптированны для работы с технической документацией. 

Для распознавания сканов существуют отдельные OCR-программы.

Для сравнения документов можно использовать, например, встроенные средства Microsoft Word. Они хорошо показывают формальные изменения текста, но не предназначены для объяснения их инженерного смысла. 

Подготовку документов можно частично автоматизировать шаблонами и отдельными средствами работы с текстом, но такие решения приходится адаптировать под конкретные формы документов и рабочие процессы.

Таким образом, необходимые инструменты существуют, но они представлены в виде отдельных программ. Их приходится настраивать, связывать между собой и адаптировать под конкретные инженерные сценарии.

Это привело меня к идее создать собственную платформу, в которой необходимые инструменты объединены в одном приложении и могут использовать результаты работы друг друга.

### Свое решение

Я выбрал формат локального приложения с отдельным инструментом для каждой типовой задачи. Пользователь выбирает нужное действие: задать вопрос, найти информацию, сравнить документы, распознать скан или подготовить служебную записку. Ему не требуется разбираться в устройстве языковых моделей, RAG и векторного поиска.

Для работы с содержанием используется языковая модель, а для операций, требующих воспроизводимого результата, — классические алгоритмы. Например, различия между документами сначала выявляются алгоритмически, после чего их можно обсудить с моделью. При подготовке документа модель помогает сформулировать текст, а программа заполняет шаблон и сохраняет файл.

Особенность Кеплера заключается в объединении функций в едином рабочем процессе. Результат распознавания можно передать в поиск или консультант, найденные сведения использовать при подготовке документа, а изменения между версиями проанализировать с помощью ИИ. Собственная разработка позволяет оперативно дорабатывать инструменты по обратной связи пользователей и адаптировать их под реальные рабочие сценарии специалистов.

Кеплер ориентирован на работу инженера с файлами, доступными на его рабочем компьютере. Локальная работа - это одно из основных ограничений проекта, связанных с требованиями информационной безопасностью корпорации.

## Реализация

| Компонент | Технологии и назначение |
| --- | --- |
| Приложение для Windows | Tauri — настольная оболочка |
| Пользовательский интерфейс | React и TypeScript |
| Логика приложения | Rust — обработка документов и координация инструментов |
| Локальные модели | llama.cpp и формат GGUF — запуск языковых и embedding-моделей |
| Хранение данных | SQLite — история, документы, индексы и результаты работы |
| Поиск | SQLite FTS5 и векторный поиск с объединением результатов |
| Распознавание текста | Tesseract OCR |

Для генерации ответов и поиска используются модели с разными задачами: языковая модель формирует текст, embedding-модель преобразует запросы и фрагменты документов в векторы для оценки смысловой близости.

**Почему выбран гибридный поиск.** В инженерных документах важны и смысл, и точные обозначения: марки материалов, номера требований, термины и числовые параметры. При исследовании подходов я пришёл к выводу, что одной векторной близости для таких задач недостаточно. Поэтому в приложении объединены полнотекстовый и семантический поиск: первый помогает находить точные совпадения, второй — связанные по смыслу фрагменты с другими формулировками.

Обработка документов, поиск, генерация и интерфейс разделены на модули. Это позволяет дорабатывать отдельные инструменты и расширять приложение по мере проверки рабочих сценариев.
